# Chat 会话报告导出设计

- 日期：2026-06-22
- 状态：已批准，待编写实施计划
- 范围：FastAPI Chat 后端、投资顾问导出服务、Next.js Chat 页面

## 1. 目标

为现有 `/chat` 增加会话报告导出能力。用户既可以点击会话标题栏中的“导出报告”按钮，也可以在聊天中用自然语言表达导出意图。LLM 必须理解完整上下文，只输出对话中最终确认的结论和行动项，排除理解错误、已被否定或被后续内容替代的信息。

当导出范围不明确时，LLM 在聊天气泡中给出可点击选项并继续澄清。范围明确后，系统无需预览或二次确认，直接生成 Markdown 并保存到项目根目录的 `report/`。

## 2. 已确认的产品决策

| 维度 | 决策 |
|---|---|
| 导出内容 | 只保留最终结论和行动项，不记录误解与修正过程 |
| 内容范围 | 由完整会话上下文与用户的自然语言意图共同决定 |
| 模糊意图 | LLM 给出 2–4 个动态、明确、互斥的可点击选项，持续澄清直到范围明确 |
| 明确意图 | 可直接导出，无需强制澄清 |
| 标题栏按钮 | 发送一条宽泛的快捷自然语言消息，因此一定先要求用户选择范围 |
| 确认流程 | 无 Markdown 预览、无编辑、无保存确认 |
| 保存目录 | 项目根目录 `report/` |
| 文件命名 | `YYYY-MM-DD-会话标题.md`；重名追加 `-2`、`-3` |
| 历史记录 | 复用现有 Chat 消息及 `tool_calls_json`，不新增导出历史表 |

## 3. 非目标

- 不导出逐字聊天记录。
- 不在 Chat 内展示或编辑待保存的 Markdown。
- 不增加导出历史、版本管理、删除或重新下载页面。
- 不允许用户指定任意服务器目录或完整文件路径。
- 不改变现有分析报告下载端点。
- 不修改 TradingAgents 分析管线或触发新的多智能体分析。

## 4. 交互流程

### 4.1 标题栏快捷入口

Chat 会话标题栏增加“导出报告”按钮。它不直接调用文件 API，而是复用现有发送消息流程，自动发送语义等价于以下内容的用户消息：

> 请根据当前会话导出报告。请先根据上下文提供可选的导出范围，不要立即导出。

因为该指令故意不指定范围，LLM 必须先提供 2–4 个范围选项。例如：

- 全部最终结论与行动项
- 仅仓位调整方案
- 仅风险控制与执行条件

这些选项由 LLM 根据当前会话中实际存在的主题动态生成，不使用固定列表。

### 4.2 自然语言入口

用户可直接输入“把最终确定的仓位调整方案导出”“将风险控制结论保存成 Markdown”等明确导出请求。Chat LLM 负责识别意图：

- 范围已经完整、具体：调用导出工具并直接保存。
- 范围仍可有多种合理解释：调用范围澄清工具并展示选项。

“总结一下”本身不自动触发文件导出；用户必须明确表达导出、保存成文档或生成 Markdown 等落盘意图。

### 4.3 选项澄清循环

LLM 每轮最多给出 4 个互斥选项。用户点击某个选项后：

1. 选项文字作为普通用户消息发送，保留在会话历史中。
2. 当前选项立即禁用，防止重复提交。
3. LLM 结合之前的导出请求、选择结果和完整会话再次判断范围。
4. 若仍有歧义，继续提供更具体的选项；否则直接导出。

只有最新一条尚未回答的选项消息可以交互。旧选项继续显示，但在出现后续消息后不可再次点击。重新打开会话时，如果最后一条助手消息仍在等待选项回答，该组选项恢复为可点击状态。

### 4.4 完成反馈

导出成功后，助手根据导出工具返回的真实结果回复：

> 已生成 `report/2026-06-22-会话标题.md`

导出失败时显示明确、可重试的错误，且不得声称文件已经生成。

## 5. 架构与组件

### 5.1 导出服务

新增聚焦于导出的独立模块，例如 `tradingagents/advisor/export.py`，提供以下职责：

- 根据完整会话和确定后的范围构造专用总结提示词。
- 调用当前配置的 Chat LLM 生成 Markdown；该次调用不绑定工具，避免递归调用导出工具。
- 生成安全、确定的候选文件名。
- 在项目根目录的 `report/` 中排他创建文件。
- 返回最终项目相对路径；失败时抛出可由 Chat 层转换为用户错误的异常。

导出模块不依赖 `api/`。API/Chat 层负责提供会话消息、会话标题、LLM 和项目路径。

### 5.2 会话级 LLM 工具

在每次 Chat 请求中，将现有数据工具与两个会话级工具共同绑定：

#### `request_export_scope(question, options)`

- 无文件或数据库副作用。
- `question` 是当前需要用户确认的单一范围问题。
- `options` 必须包含 2–4 个明确、互斥、与当前会话主题相关的选项。
- 工具调用参数通过现有 `tool_calls_json` 持久化，供前端恢复按钮。

#### `export_chat_report(scope)`

- 仅在导出范围明确时调用。
- `scope` 是完整、自洽的范围描述，不能只写“A”或“第一个选项”。
- 工具闭包持有当前 `session_id`，从服务端 store 读取完整消息与最新标题。
- 调用导出服务生成并立即保存报告。
- 返回真实的项目相对路径，供 LLM 形成最终回复。

这两个工具不加入全局 `ADVISOR_TOOLS` 常量，而是在请求内构造，避免跨会话状态泄漏。

### 5.3 Chat 引擎与持久化

继续使用现有 `run_chat()` 工具调用循环和 SSE 通道。所需扩展仅包括：

- 接受请求级工具集合。
- 将内部导出工具的调用参数包含在最终 `tool_calls` 中。
- 工具失败时产生现有 `error` 事件或明确的工具失败结果，且不能持久化虚假的成功回复。

不新增数据库表。`request_export_scope` 的结构化选项复用 `chat_messages.tool_calls_json`。Chat 消息响应模型保持兼容；前端从工具名和参数读取选项。

### 5.4 前端组件

`webui/app/chat/page.tsx`：

- 在当前会话标题栏加入“导出报告”按钮。
- 按钮复用 `send()` 的消息发送路径，而非新增导出请求路径。
- 会话尚未出现一轮完整助手回复、正在流式响应或正在删除时禁用按钮。
- 点击范围选项时，复用普通消息发送流程。

`webui/components/chat/ChatMessage.tsx`：

- 识别 `request_export_scope` 工具调用并在助手内容下渲染按钮。
- 仅为最新、未回答的选项开放点击。
- 从“数据来源”显示中排除 `request_export_scope` 和 `export_chat_report`；现有市场数据工具的来源显示保持不变。

前端不接收、保存或编辑生成的 Markdown 内容。

## 6. 总结提示词规则

导出 LLM 调用接收截至当前导出指令的完整会话，包括范围澄清消息。专用系统提示词必须明确要求：

1. 仅输出用户最终确认的结论与行动项。
2. 较新的明确确认覆盖较早的冲突内容。
3. 排除误解、被否定内容、已废弃方案、试探性建议和修正过程。
4. 严格遵守 `scope`，不顺带加入范围外主题。
5. 不补充会话中没有依据的事实、价格、日期或建议。
6. 不把导出指令、选项澄清过程或工具状态写进报告。
7. 输出完整 Markdown，至少包含一个标题；只在会话确有对应内容时生成“最终结论”和“行动项”等小节。

如果确定范围内不存在可导出的最终结论，导出服务不得创建空报告。工具返回“没有已确认内容”的可解释失败，由 LLM 在聊天中提示用户继续讨论或选择其他范围。

## 7. 文件保存规则

- 日期使用服务器当前本地日期，格式为 `YYYY-MM-DD`。
- 标题使用保存时最新的 Chat 会话标题。
- 清除 `/\\:*?\"<>|`、控制字符、首尾空白和结尾句点，并限制标题长度。
- 清理后为空时使用 `chat-report`。
- 保存目录固定为项目根目录的 `report/`；目录不存在时创建。
- 首个候选名为 `YYYY-MM-DD-标题.md`，已存在时从 `-2` 开始递增。
- 使用排他创建完成“检查并写入”，绝不覆盖已有文件；并发冲突时继续尝试下一个序号。
- 先在内存中完成 LLM 生成和内容校验，再创建目标文件，避免失败后留下空文件。
- API 和工具只返回项目相对路径，不接受客户端提供的目录或文件名。

## 8. 错误处理

- LLM 生成失败：不创建文件，Chat 显示可重试错误。
- 生成内容为空或没有最终结论：不创建文件，提示用户选择其他范围或先完成讨论。
- 创建目录或文件失败：返回真实文件系统错误的安全摘要，不泄露不必要的系统细节。
- 重复点击：流式期间禁用发送和导出；已回答的历史选项不可再次点击。
- 工具参数不合法：将调用视为失败，不静默修正为可能改变范围的内容。
- Chat 客户端断开：已开始的工具调用遵循现有后台线程语义；只有写入成功后才记录成功回复。

## 9. 测试策略

### 9.1 导出服务单元测试

- 文件名包含服务器本地日期和清理后的会话标题。
- 非法字符、空标题、过长标题得到安全名称。
- 连续同名导出生成基础名、`-2`、`-3`，已有文件内容不被覆盖。
- 并发排他创建不会产生覆盖。
- LLM 失败、空输出和无已确认内容时不留下文件。
- 提示词包含冲突覆盖、排除误解、遵守范围和禁止编造规则。

### 9.2 Chat 引擎与路由测试

- 宽泛按钮消息导致 `request_export_scope`，产生 2–4 个选项且不写文件。
- 模糊自然语言请求可以经过多轮选项继续澄清。
- 明确自然语言请求直接调用 `export_chat_report`。
- 工具使用 store 中的完整会话，而不是客户端提交的历史。
- 导出成功回复包含工具返回的真实相对路径。
- LLM 或文件系统失败时没有成功消息和残留文件。
- 导出工具按请求创建，不泄漏其他会话的 ID、标题或内容。

### 9.3 Store 与前端验证

- `tool_calls_json` 可持久化并恢复范围问题和选项。
- 只有最新且尚未回答的选项可点击；历史选项禁用。
- 点击选项发送一次普通用户消息，流式期间防重复。
- 内部导出工具不显示为数据来源。
- 空会话、流式中和删除中的导出按钮正确禁用。
- 普通 Chat、现有数据工具、多报告上下文和会话重开行为不回归。

### 9.4 验证命令

- `.venv/bin/python -m pytest -m \"not integration\"`
- `.venv/bin/ruff check .`
- `cd webui && npm run lint`
- `cd webui && npm run build`

## 10. 成功标准

- 用户可以从标题栏按钮或明确自然语言进入导出流程。
- 模糊范围不会被猜测；LLM 用可点击选项澄清到明确为止。
- 最终文件只含范围内已确认的结论和行动项，没有已纠正的错误内容。
- 文件自动保存到 `report/`，命名包含当前日期且不覆盖同名文件。
- 整个流程不出现 Markdown 预览、编辑或保存确认步骤。
